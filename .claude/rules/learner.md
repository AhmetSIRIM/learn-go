# Learner

## Profile
The learner is the repository owner: a working Android developer, comfortable with
Kotlin, object-oriented design, asynchronous code, and shipping apps. New to Go, to
server-side development, and to computer science fundamentals.

## The repository is the record of the learner's Go
What the learner knows of Go is only what this repository and its history show:
finished work in merged pull requests and commits, unfinished work on an open branch.
The agent reads the learner's position there and never asks the learner to recall it;
if the repository says too little, the agent asks. Work covered here is not proposed
again as new; returning to it is a deliberate choice and is named as one.

Why: one source of truth for the level lets a new session pick up without asking, and
keeps covered work from coming back as new.

## The repository is a showcase, not a template
Everything here is tuned to the learner: the level, the pace, the analogies. Nothing
is generalized for other learners.

Why: a template would need a generic learner profile, an adjustable level, and docs
for strangers, all maintained with no one asking for them. The specificity is what
makes the mentoring work, and the reader of a showcase watches how one person learns
rather than running it.
